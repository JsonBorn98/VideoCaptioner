# 04: 建立问题主体、上下文和批次规划

**What to build:** 让后处理把完整字幕中的观看问题规划为批量修复请求。每个问题保留独立身份，以问题区域作为修复主体，并按上游 `boundary_context_radius` 向上下扩展边界上下文；主体重叠时合并，容量不足时按既定顺序收缩。

**Blocked by:** 01, 02

**Status:** resolved

- [ ] 扫描结果可以同时包含长度、速度、语义和结构问题，并为每个问题建立稳定身份。
- [ ] 每个问题的主体与上下文分开表达，上下文默认不成为修改目标。
- [ ] 上下文范围直接复用任务快照中的 `boundary_context_radius`，不产生第二套用户设置。
- [ ] 主体重叠或相邻时合并主体，同时保留原问题 ID、原因和区域级验收关系。
- [ ] 仅上下文重叠而主体独立时保持主体独立并允许共享上下文。
- [ ] 请求容量不足时先减少主体数量，再逐步减少上下文；单个主体仍无法容纳时明确报告容量不足并保留完整文本。
- [ ] 规划结果可以被 fake gateway 直接观察，验证批次内容和边界身份。
