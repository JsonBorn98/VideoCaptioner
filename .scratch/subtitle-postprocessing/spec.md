# 字幕后处理职责与观看约束重构

## Problem Statement

当前字幕生成链路把观看用长度限制放在翻译输入分段中，后处理又没有统一接管显示长度、显示分段和阅读体验。结果是初版字幕可能已经超长，后处理无法可靠修复；原文保护、译文重写、上下文范围和重试语义也分散在不同模块中。

独立后处理还是高频使用场景。用户通常把视频、字幕和上游过程结果放在同一任务目录附近，直接调用后处理，而不是先运行完整 workflow。现有过程文件散落在普通输入输出目录，缺少可验证的任务身份，也没有把完整 workflow、独立调用和失败回退统一起来。

## Solution

让字幕后处理成为观看约束的唯一负责模块。翻译优化只产出保留完整内容的初版字幕；后处理读取初版字幕，扫描观看问题，以问题区域为主体并带上上下文批量修复，拼接回完整字幕后重新验收。原文只允许拆分，译文允许按原翻译方式重译、校订和改写。

后处理通过一个深的核心任务入口统一编排布局识别、配置快照、过程资产发现、确定性处理、模型修复、质量验收、局部回退、报告和持久化。CLI、Qt workflow 和独立 GUI 是适配器，只负责装配输入、展示状态和触发用户导出。

独立调用默认在输入视频或字幕旁创建并读取 ASCII 目录 `videocaptioner-workspace`。过程资产按规范化任务名、输入指纹和语言对组织，并由 manifest 验证关系。整个后处理模块成功完成后才允许导出过程资产；运行中、取消、模块级失败或仅有局部未解决问题时，过程文件留在过程目录中供用户自行查找。

## User Stories

1. 作为翻译用户，我希望翻译优化保留原文和译文的完整内容，以便后处理可以在完整语义上独立决定显示分段。
2. 作为翻译用户，我希望初版字幕不被观看限长逻辑截断或改写，以便内容准确性和观看呈现各自有清晰职责。
3. 作为后处理用户，我希望原文在整个处理过程中保持字词、标点和顺序不变，以便字幕仍能与原始对白核对。
4. 作为后处理用户，我希望过长原文可以拆成多个字幕段，以便在不改写原文的情况下改善显示效果。
5. 作为后处理用户，我希望译文可以在必要时重译、校订或改写，以便同时满足语义质量和观看约束。
6. 作为双语字幕用户，我希望原文侧和译文侧可以分别选择单行限长或自动换行，以便适配不同播放器和显示布局。
7. 作为单行限长用户，我希望中英文分别拥有目标长度上限和绝对长度上限，以便用软目标优化、用硬上限验收。
8. 作为混合语言用户，我希望长度使用折算字符数和混合语言有效阈值，以便中英文混排不会被单一词数口径误判。
9. 作为自动换行用户，我希望后处理完全跳过该显示侧的长度和行数处理，以便把换行和实际渲染交给播放器。
10. 作为后处理用户，我希望自动换行仍保留阅读速度、语义质量和其他已启用能力，以便显示策略不会意外关闭整个后处理模块。
11. 作为后处理用户，我希望系统扫描完整字幕并一次汇集所有问题，以便模型可以同时理解多个问题及其所在上下文。
12. 作为后处理用户，我希望每个问题保留独立身份、原因、上下文和验收状态，以便批量请求不会造成问题归属混乱。
13. 作为后处理用户，我希望每个问题主体上下各纳入上游 `boundary_context_radius` 个字幕段，以便边界处的翻译质量保持连贯。
14. 作为后处理用户，我希望上下文只作为边界参考而不是默认修改目标，以便相邻的已通过字幕不被无故改写。
15. 作为后处理用户，我希望相邻或重叠的问题合并主体并保留各自问题 ID，以便一次请求不会产生互相冲突的修复。
16. 作为后处理用户，我希望模型修复可以让一个输入字幕段变成多个输出字幕段，以便原文拆分和译文重组能够表达完整结果。
17. 作为后处理用户，我希望模型输出的原文片段按顺序拼接后与输入原文等价，以便拆分不会偷偷删除或改写原文。
18. 作为后处理用户，我希望拆分时间由后处理根据阅读负荷和可信时间证据确定，以便模型不能直接破坏时间轴。
19. 作为后处理用户，我希望没有足够时间证据时，无法同时满足最短时长和语义边界的片段保留原段并报警，以便系统不制造不可播放的时间轴。
20. 作为后处理用户，我希望增强型上游翻译的修复继续使用主翻译和高级校对流程，以便修复质量与原任务一致。
21. 作为后处理用户，我希望普通上游翻译不被静默升级为增强流程，以便任务配置的成本和质量边界保持稳定。
22. 作为独立后处理用户，我希望系统优先发现输入旁过程目录中的上游资产，以便不必重复输入翻译方式、术语和上下文信息。（勘误 2026-09-15：「上下文信息」即 D07 未获确认的全文简报，同日裁决不作为上游资产，见验收决策行勘误。）
23. 作为独立后处理用户，我希望资产必须通过 manifest、指纹、语言对和可读性验证，以便同目录中的旧任务文件不会被误用。
24. 作为独立后处理用户，当所需资产缺失时，我希望得到明确缺失项并能显式补充资产，以便独立调用仍可完成确定性处理或仅报告。
25. 作为后处理用户，我希望第一次修复提交属于正常流程而不占用重试次数，以便默认预算表示真实失败后的修复机会。
26. 作为后处理用户，我希望第一次失败后最多有 4 次业务修复重试，以便重试口径与上游保持一致且预算可预测。
27. 作为后处理用户，我希望网络和限流重试独立于业务修复重试，以便传输暂时失败不会错误耗尽问题修复预算。
28. 作为后处理用户，我希望每轮都把候选拼回完整字幕并重新验收，以便下一轮只处理仍未解决的问题。
29. 作为后处理用户，我希望重复候选、重复指纹或无法改善的候选立即停止，以便修复循环不会震荡或浪费请求。
30. 作为后处理用户，我希望耗尽预算的问题区域恢复后处理开始时的原始未拆分快照，以便失败的中间拆分不会污染交付结果。
31. 作为完整 workflow 用户，我希望成功修复和局部回退可以组合成活动字幕继续下游合成，以便局部问题不会阻断整个任务。
32. 作为完整 workflow 用户，我希望模块级失败、初版无效或主动停止仍能明确阻断下游，以便不把不可用结果当作成功交付。
33. 作为后处理用户，我希望未解决问题在报警和 QA 报告中明确列出且不被记为通过绝对上限，以便我知道哪些区域需要人工处理。
34. 作为后处理用户，我希望过程资产集中在专用目录而不污染普通输入输出目录，以便任务文件保持整洁。
35. 作为后处理用户，我希望过程目录和文件名使用稳定的 ASCII 规范，以便跨操作系统显示和识别一致。
36. 作为后处理用户，我希望模块运行期间不出现过程资产导出选项，以便中间状态不会被误当作最终交付。
37. 作为后处理用户，我希望整个模块成功完成后可以按 manifest 选择并复制过程资产，以便需要时获得明确的交付副本。
38. 作为设置用户，我希望旧观看长度参数和原文改写开关彻底删除，以便不会继续存在互相冲突的配置入口。
39. 作为升级用户，我接受旧配置不迁移而直接使用新的后处理默认值，以便实现保持单一配置语义。
40. 作为维护者，我希望 CLI、GUI 和 workflow 共享同一核心任务入口，以便行为、错误、回退和报告不会因调用方式不同而漂移。
41. 作为维护者，我希望核心入口可注入网关、时间证据、配置方案库和资产适配器，以便测试可以观察真实请求形状而不依赖环境变量。
42. 作为维护者，我希望所有外部行为测试通过核心任务入口完成，以便修改内部规则时保留较高层次的回归保护。

## Implementation Decisions

- 后处理模块的唯一外部测试切面是一个深的任务运行入口。它接收字幕任务、布局信息、冻结的后处理配置和可选的网关、时间证据与过程资产适配器，返回活动字幕、报告、问题状态、警告和是否允许下游继续。
- 核心入口统一完成：导入与结构识别、输入快照、配置冻结、过程资产发现、确定性后处理、长度与速度扫描、问题规划、批量模型修复、结果拼接、全量验收、局部回退、过程文件保存和最终状态发布。
- `run_post_stage` 作为核心入口内部的确定性规则管线保留，不作为第二套前端契约。CLI、Qt workflow、独立 GUI 和导出操作都通过任务入口产生的结果和状态工作。
- 初版字幕是不可变输入成果。后处理开始时保存整段输入快照；每个问题区域同时保存区域级原始字幕和时间轴快照，回退只使用该快照。
- 显示侧分别保存单行限长或自动换行策略。自动换行侧不执行长度和行数扫描；单行侧使用折算字符数、目标上限和绝对上限。CJK/全角字符计 1，拉丁字母、数字、半角标点和空格计 0.5，空白及零宽格式字符计 0，其他符号计 1；混合语言阈值按内容占比计算。
- 问题规划以问题区域为修复主体，向上下扩展任务快照中的 `boundary_context_radius` 个相邻字幕段。上下文与主体分开标识，不作为默认修改目标；多个问题可以共享上下文。
- 批次规划复用上游的容量收缩顺序：先减少主体数量，再逐步减少上下文范围。单个主体在零上下文下仍超出预算时，报告容量不足，不截断字幕内容。
- 批次响应必须显式包含问题 ID、输出段序号、原文片段和译文片段。一个主体可以对应多个输出段。原文片段顺序拼接后必须等价于输入原文，输出时间由核心规则和时间证据决定。
- 每次修复都先把候选结果拼接回完整字幕，再执行结构、原文等价、语义、绝对长度和阅读速度验收。只有仍未解决的问题进入下一轮；候选必须消除至少一个问题且不能重新引入已通过的硬约束。
- 初始修复提交不计入业务重试。首次失败后默认允许 4 次业务修复重试；网络、限流和传输重试使用独立边界。上游同类业务重试统一采用相同口径。
- 修复耗尽时，只有对应区域恢复其后处理开始时的原始快照；其他成功区域保留。结果状态同时包含未解决问题、报警和报告记录，完整 workflow 继续下游。
- 修复方式从任务开始时冻结的翻译执行快照中选择。增强型翻译使用主翻译加高级校对，普通 LLM 翻译使用普通翻译方式，非 LLM 翻译不静默升级为 LLM。独立任务缺少可验证翻译资产时，只执行可用的确定性处理、仅报告或明确报告无法自动重译。
- 过程资产根目录固定为输入资产旁的 ASCII `videocaptioner-workspace`。任务目录由规范化任务名、输入指纹和语言对组成；manifest 保存输入相对标识、指纹、语言对、翻译方式、生成时间、软件版本和资产清单，不保存 API key、完整 prompt、模型响应或推理内容。
- 资产发现必须同时验证 manifest、资产内容和当前输入关系。过程文件包括术语、审计、检查点、翻译执行快照、上下文、QA 报告和后处理状态，均留在过程目录；成功后导出是依据 manifest 的显式复制动作。（勘误 2026-09-15：「上下文」出自 D07 未获确认的全文简报复用建议，本行误写为清单事实；同日裁决从 `UPSTREAM_ASSET_KINDS` 移除 `context`，全文简报复用需要时另行决策重新加回。）
- 阶段自动保存与用户导出分离。模块成功完成前不导出过程资产；模块取消、模块级失败或未完成时不提供导出。完整 workflow 的活动字幕仍由核心结果直接传递给下游。
- 旧的观看限长参数、上游观看限长传递、原文改写开关及其消费逻辑整体删除，不保留兼容读取或迁移。上游仍可保留服务内容语义分段和模型请求容量的机制，但不再读取观看限长。
- 配置、资产发现、模型网关、报告写入和 UI/CLI 输出使用适配器注入或薄适配层，核心入口不依赖 Qt、命令行输出或特定播放器。

## Testing Decisions

- 测试只验证外部行为和任务结果，不锁定内部函数调用顺序、私有数据结构或文件实现细节。测试优先穿过唯一的核心任务入口，使用临时输入和 fake gateway、fake asset store、fake timing evidence 验证完整行为。
- 核心任务测试覆盖单语/双语结构、布局指定、初版不可变、每侧显示策略、自动换行跳过长度约束、折算字符数、混合语言阈值和无效初版的失败语义。
- 修复测试覆盖问题主体与上下文分离、`boundary_context_radius` 复用、主体重叠合并、共享上下文、容量收缩顺序、一对多输出、原文等价、确定性时间分配和最短时长失败回退。
- 重试测试必须区分正常初始提交、4 次业务修复重试和独立网络重试；测试首次失败后的计数、预算耗尽、重复候选、局部回退、未解决报告和继续下游。
- 翻译执行快照测试覆盖普通翻译、增强型翻译、非 LLM 翻译和独立任务缺少资产时的行为，确认后处理不静默改变翻译方式。
- 过程资产测试使用临时输入目录，覆盖 ASCII 目录创建、任务名和指纹隔离、manifest 验证、错误资产拒绝、缺失资产提示、运行中不导出、成功后按 manifest 导出和失败时不导出。
- 适配层测试只验证 CLI、Qt workflow 和独立 GUI 能正确装配核心任务、发布活动字幕和展示警告；不在每个适配层重复验证修复算法。
- 旧配置删除测试确认旧观看参数、原文改写配置和上游观看限长调用链不再被读取；新配置缺省值可直接创建有效任务，不执行迁移。
- 既有后处理、翻译、任务工厂和 CLI 测试作为回归基线运行；新增核心行为测试优先放在后处理功能测试目录，并在完成实现后运行 Ruff、Pyright 与非集成 pytest。

## Out of Scope

- 翻译内容质量算法本身、主翻译和高级校对的既有实现不在本规格内；本规格只定义后处理如何选择并复用其执行方式。
- 播放器字体、字号、像素宽度、最终换行和渲染效果不由后处理保证。
- ASS 样式、字体、颜色、定位、特效和卡拉 OK 语义不属于模块交付字幕；样式化导出仍由字幕样式模块负责。
- 用户旧配置的迁移、凭证导入和旧过程文件的全盘清理不在范围内。
- 过程资产的跨机器同步、云端存储、缓存驱逐策略和多进程并发策略不在范围内。
- 自动将未解决问题交给人工编辑器或暂停整个 workflow 不在范围内；本规格要求报警、报告和局部回退后继续下游。

## Further Notes

- 设计依据为已接受的后处理职责 ADR 和持续设计记录。持续设计记录中的 D01-D28 是产品与架构决策的权威来源；本规格将其转换为可实现的任务接口和测试契约。
- 当前实现仍存在逐条一对一修复、旧观看长度调用链、普通输出目录过程文件和不一致重试计数等差距。实现票据应按依赖顺序先建立核心任务契约与资产模型，再迁移修复、配置和各适配器。
- 过程目录中的文件是机器本地过程数据。任何包含凭证、模型响应或完整 prompt 的内容都必须继续遵守仓库的日志与本地数据安全约束。
