## Answer

调研完成，设计方案：.scratch/llm-profile-unification/research/06-gateway-disk-cache-design.md（ticket 03 落地请读它，落地清单在其 §五）。六点裁决：(1) 缓存键——内容寻址 sha256，素材=显式 allowlist 两级：profile 请求塑形字段（transport/dialect/base_url/api_key/model/openai_endpoint/request_options；排除 profile_id/name/work_context_tokens/max_concurrency）+ request 字段（messages/max_output_tokens/response_schema/request_options_override/cacheable_system_prefix；排除废弃 temperature 与观测标签 metadata）。api_key 全量入键（明文不落盘，digest 单向；能摸缓存目录者本就能摸 llm_model_profiles.json 明文，无新增暴露面）修掉 call_llm memoize 键不含连接信息的洞；键素材带 key_version="gateway-cache-v1"，请求构造逻辑变更即 bump 全量作废。不用 asdict()（temperature/metadata 会混入）。(2) LLMResult 序列化——落盘 JSON {"schema","text"}：只存 text；raw 在 src/tests 零消费者且 pickle 耦合 SDK 布局，丢弃；usage 不存、命中回放 LLMUsage() 全 None（计费报告只记真实花费，__add__ 对全 None 恒等无害），与 cache_hit 日志无 usage 口径一致。(3) profile 编辑失效——内容寻址使失效问题构造性消失：编辑任何请求塑形字段自动换 digest 旧条目不可达；非键字段（name 等）不影响响应不该失效；卫生靠 expire=3600 自然回收，不做 tag_index/按 profile_id evict/profile store 挂钩（否决：收益只剩提前回收 <1h 垃圾，代价是 store↔cache 新耦合）。(4) 失败与能力测试、连接测试语义——只缓存 complete() 正常返回（INVALID_RESPONSE 在 gateway 重试层拦截走不到 store，异常不缓存与 memoize 平价）；expire=3600 平价锚点；app 层解析失败不驱逐缓存（同请求重试快速失败省预算，cap/reasoning 升级改请求=不同键真实重试，旧 memoize 同此行为）；两处测试（check_llm.py:172-202 能力测试、:205-240 连接测试）经 complete() 新 keyword 参 use_cache=False 双向旁路——测试验证当下链路，读缓存会在 provider 已宕时给假信号。(5) cache_hit 日志——request_logger 新函数 log_gateway_cache_hit()，条目 {time, request_id, stage/role 照当次 metadata, status:"cache_hit", profile:{id,model}, duration_ms:0}，无 usage 无 attempt；include_content 开启时附缓存文本与成功条目对称。(6) 全局开关联动+目录——复用 is_cache_enabled()，lookup/store 双侧判（关=不读不写照抄 memoize wrapper）；新 Cache 实例 CACHE_PATH/"llm_gateway" + get_gateway_cache()，不混 llm_translation 旧目录（旧键正是被修的洞）；conftest pytest_unconfigure 注册 close，03 顺带删 get_llm_cache（memoize 本体保留，test_cache_validation 直测）。实现形态：新模块 core/llm/response_cache.py（GatewayResponseCache），LLMGateway.complete() 增 use_cache=True，lookup 在信号量/adapter 之前、成功后 store；fail-open 铁律：缓存一切异常捕获降级当 miss/放弃写入，绝不打断请求路径（超越旧 memoize 无保护的一处）。翻译路径现状零磁盘缓存（gateway 直连 adapter），缓存是新增省钱能力非平价迁移。关键事实依据：memoize 键不含 base_url/api_key（client.py:190, cache.py:72-105）；LLMResult.raw 零消费者；usage 被 orchestrator.py:813 计费累加；cacheable_system_prefix 改变请求体（adapters.py:665-668, 889-893）；temperature 废弃字段 adapter 不序列化（models.py:278-279）；全局开关三处拨动（ui/main.py:71-74, setting_interface.py:851-868, tests/conftest.py:27）。遗留低风险不阻塞：增强翻译跨 run 命中率取决于 cap 阶梯重现（省钱率不可承诺，无正确性问题，llm_requests.jsonl 的 cache_hit 行天然是度量）；diskcache 多进程并发理论安全留 03 实现验证。
