# 15 - 旧服务页移除与工具模型卡

**构建什么.** GUI 侧收尾：旧服务页（setting_interface.py 的 llmGroup 卡组）四层全删，工具模型卡上位。旧页移除：UI 组与 22 张凭证卡及检查连接按钮与回调线程（LLMConnectionThread）、cfg 全部 22 个键、task_factory 装配段旧逻辑（7 服务 if/elif 分支与 utility 三标量传递）、相关测试断言；共用的控件类（如转录组也在用的输入框卡）保留。settings.json 已写入的 LLM.* 键值留盘成死数据，不迁移不清理（qconfig 容忍未知键）；凭证不迁移——新方案体系已覆盖旧配置全部信息，用户需要时在方案编辑器手填。新增工具模型卡：翻译设置页页签区上方的一张顶层共享卡（不嵌进任何页签——断句、优化在三种翻译方式下都运行），复用既有方案选择卡组件（ProfileSelectionCard），新增绑定键 utility_llm_profile_id；下拉默认项「跟随主翻译模型」即空绑定（解析器派生路径），选独立方案即覆盖；解析器 fail-fast 的错误文案指向这张卡。方案编辑器模型框从纯输入升级为可编辑下拉，旁加「获取模型列表」按钮：复用 get_available_models 按方案的 base_url/api_key 拉取填充，走既有能力测试线程模式防 UI 阻塞；拉取失败只提示不阻塞保存；旧页「检查连接」的能力由编辑器既有能力测试按钮承接。
