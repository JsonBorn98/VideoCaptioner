# 能力测试三态判定、输出上限探查与连接测试挂载

## 问题陈述

我在模型配置方案里配置「最大输出 token」（请求输出上限）时，并不知道 provider 侧这个模型实际接受的模型输出上限是多少。凭感觉或照抄文档配大了，真实任务必然被 400 拒绝。而现在的能力测试只有「通过/失败」两态：撞到模型输出上限的 400 和其他失败混在一起，我看不出是哪个配置项超了、该改成多少；任何「换个值就能过」的测试口径还可能让一个真实任务必挂的配置拿到绿灯，误导我直接开跑任务。

同时，模型方案编辑器里没有任何办法发现模型输出上限，我只能去翻 provider 文档或反复试错；任务开始前也没有连通性检查，API key 填错、Base URL 打错这类问题要等 ASR 跑完、进入 LLM 阶段才暴露，白白浪费一次任务。

## 方案

把原本混在一起的「测试」拆成三个行为明确分叉的操作（ADR 0016、ADR 0017）：

1. **能力测试**（模型方案编辑器内，现有按钮升级）：分别发送一次文本请求和一次结构化请求验证当前配置，原样采用请求输出上限，错误透传真实原因；结论从两态升级为三态——**通过 / 需调整 / 失败**。「需调整」专指请求输出上限超出模型输出上限的情形，由 LLMCallError 携带的输出上限提示驱动，展示两个上限的对比；绝不因「换个值就能过」而报「通过」——原配置在真实任务中必然 400。
2. **输出上限探查**（模型方案编辑器内，最大输出 token 配置行旁新增按钮）：向 provider 探测模型输出上限——以工作上下文-1 发起探查请求，从被拒的 400 错误体解析出模型输出上限，折算建议值 = min(解析值, 工作上下文-1)，再用建议值做一次验证重试确认可信；仅当已配置的请求输出上限超出模型输出上限时把建议值自动填入配置项（低于时不抬升，自动档不引入显式上限），不自动保存方案。
3. **连接测试**（任务开始前）：对经工具角色解析出的绑定模型配置方案发送单次小请求验证连通性，错误只透传真实原因——不做验证重试、不产生建议值；失败时展示真实错误并中止本次任务启动，可重试。

## 用户故事

1. 作为一个字幕制作者，我想要能力测试在请求输出上限超出模型输出上限时结论报「需调整」并展示两个上限的对比，以便一眼看出该调小哪个配置项，而不是误以为模型或网络坏了。
2. 作为一个字幕制作者，我想要能力测试绝不因「换个值就能过」而报「通过」，以便绿灯永远意味着当前配置原样能跑真实任务。
3. 作为一个字幕制作者，我想要能力测试原样采用我配置的请求输出上限（不偷偷改小再测），以便测试结论真实代表当前配置。
4. 作为一个字幕制作者，我想要能力测试的非超限错误透传服务端真实原因，以便直接看到服务端到底报了什么。
5. 作为一个字幕制作者，我想要能力测试的文本与结构化两项结果独立给出结论，以便知道具体是哪一项能力不满足。
6. 作为一个字幕制作者，我想要三种接口格式（OpenAI 兼容、Anthropic Messages、Gemini）的输出侧超限 400 错误体都能被解析出模型输出上限，以便无论选哪家 provider，能力测试与输出上限探查行为都一致。
7. 作为一个字幕制作者，我想要在最大输出 token 配置行旁一键发起输出上限探查，以便不用翻 provider 文档就知道模型输出上限是多少。
8. 作为一个字幕制作者，我想要探查解析出的模型输出上限经 min(解析值, 工作上下文-1) 折算成建议值，以便建议值既不超过模型实际接受的上限、也不超过工作上下文约束。
9. 作为一个字幕制作者，我想要建议值先经一次验证重试确认可信、再允许填入，以便不会把一个真实任务跑不通的值写进配置。
10. 作为一个字幕制作者，我想要仅当已配置的请求输出上限超出模型输出上限时建议值才自动填入，低于时探查不抬升我的配置，以便保守配置不被悄悄改大。
11. 作为一个字幕制作者，我想要未配置请求输出上限（自动档）时输出上限探查只展示发现的模型输出上限、不自动引入显式上限，以便自动档行为不被悄悄改变。
12. 作为一个字幕制作者，我想要输出上限探查的填入不自动保存方案，以便还能对比原值、反悔或手动调整后再保存。
13. 作为一个字幕制作者，我想要输出上限探查发起前有费用提示（可能发出探查与验证重试两次请求），以便不产生意料之外的账单。
14. 作为一个字幕制作者，我想要探查请求未被 400 拒绝时（provider 接受了工作上下文-1 的高上限）得到「模型输出上限不低于探查值」的结论且不改动配置，以便理解这个边界情形而不是看到莫名的失败。
15. 作为一个字幕制作者，我想要 400 错误体里解析不出模型输出上限时看到透传的原始错误、不产生建议值，以便自己判断服务端的真实情况。
16. 作为一个字幕制作者，我想要任务开始前自动对绑定模型配置方案发送单次小请求做连接测试，以便不在 ASR 跑完之后才发现 API key 或 Base URL 填错。
17. 作为一个字幕制作者，我想要连接测试遵循工具角色的方案解析——独立工具绑定优先，无绑定从主翻译方案派生，皆无则给出带指引的报错，以便我单独绑定的工具方案同样被验证到，且不会静默回退。
18. 作为一个字幕制作者，我想要连接测试用与真实任务相同的请求通道（同一套 LLM 网关与适配器），以便测试结论能代表真实任务的行为。
19. 作为一个字幕制作者，我想要连接测试失败时看到服务端真实报错、且本次任务不启动，以便立刻知道该修什么而不是浪费一次任务。
20. 作为一个字幕制作者，我想要连接测试失败后可以重试启动，以便瞬时网络问题不会永久挡住任务。
21. 作为一个字幕制作者，我想要连接测试不做任何验证重试、降值或建议值，以便测试绿灯严格等价于「配置本身能完成一次请求」。
22. 作为一个批量任务用户，我想要批量启动时连接测试只做一次（批量内方案不变），以便不逐文件重复付费。
23. 作为一个字幕制作者，我想要纯转录等不使用 LLM 的任务类型跳过连接测试，以便没有 LLM 配置也能正常开始任务。

## 实现决策

- LLM 适配器层为三种接口格式新增输出侧超限解析：从 400 错误体解析出模型输出上限，作为结构化字段挂到 LLMCallError 上，并使用与输入侧超限（CONTEXT_LIMIT）区分的错误类别；解析遵循输入侧超限标记的既有先例，解析不出数值时错误原样透传、绝不猜测。
- LLMCallError 成为模型输出上限事实的唯一携带通道：能力测试的「需调整」判定与输出上限探查的解析都读这个结构化字段，不做错误文本二次匹配。
- 能力测试保持现有双探针（文本 + 结构化）形态与费用确认，原样采用请求输出上限；结论升级为三态：通过 / 需调整 / 失败。「需调整」仅由携带模型输出上限的错误触发，展示模型输出上限与请求输出上限的对比；两项探针结论独立呈现（ADR 0016）。
- 输出上限探查是能力测试模块新增的独立入口：以工作上下文-1 作为请求输出上限发起单次探查请求 → 取错误携带的模型输出上限 → 建议值 = min(解析值, 工作上下文-1) → 用建议值做一次验证重试 → 重试通过才允许填入；探查请求未被拒时报告「不低于探查值」且不改动配置；解析不出时不产生建议值、错误透传（ADR 0017）。
- 模型方案编辑器在最大输出 token 配置行旁新增「输出上限探查」按钮：发起前费用确认；建议值仅在已配置请求输出上限且超出模型输出上限时填入，低于时不抬升，自动档只展示不填入；填入不自动保存方案。
- 连接测试挂载于任务开始入口（GUI 单任务启动与批量启动）：方案经工具角色解析器解析（ADR-0014 顺序：独立工具绑定优先 → 从主翻译方案派生 → 皆无抛带指引异常）；单次小请求经 LLM 网关发出；失败展示真实错误并中止本次启动，可重试；批量启动只测一次；不使用 LLM 的任务类型跳过；连接测试随任务启动自动发起，不逐次弹费用确认（单次小请求）。
- 连接测试函数的现有行为（单次、透传、同一套适配器）已符合 ADR 0017，本期只做挂载与展示，不改其语义。
- UI 沿用现有探针线程模式（后台线程 + 信号回填结果），能力测试与输出上限探查进行中禁用相应按钮，不阻塞编辑器表单。

## 测试决策

- 好测试只测外部行为：主 seam 用假网关按脚本返回结果或抛错，断言「发了什么请求、结论是哪一态、重试了几次」，不断言内部函数调用或私有状态；次 seam 用注入的 session/client 构造真实形状的 400 错误体，断言解析出的结构化字段、错误类别与脱敏（敏感错误体不进异常文本）。
- 主 seam（现有，不新建）：能力测试模块的 LLM 网关注入点。覆盖三态判定（需调整由携带模型输出上限的错误驱动、其余失败透传原因）、建议值折算 min(解析值, 工作上下文-1)、输出上限探查的请求形状（以工作上下文-1 发起）与验证重试序列（探查 → 解析 → 建议值重发恰好一次 → 通过才可填入）、探查未被拒与解析不出的边界、连接测试恰好一次请求且无重试。先例：现有连接测试与双探针假网关测试。
- 次 seam（现有，不新建）：LLM 适配器的 session/client 注入点。覆盖三种接口格式的输出侧超限 400 解析出模型输出上限、与输入侧超限类别的区分、解析不出时不猜数值、错误体脱敏。先例：现有输入侧超限类别测试。
- UI 层不新建 seam：沿用现有 offscreen QApplication 测试先例，轻量覆盖三态结果文案（含上限对比）、建议值填入与不抬升、自动档只展示、探查/测试中按钮禁用、连接测试失败中止与可重试、纯转录跳过、批量只测一次。

## 范围外

- CLI 任务开始的连接测试挂载（本期只挂 GUI 入口）。
- 通过 provider 模型元数据接口发现模型输出上限——模型输出上限作为事实仅来自 400 错误体解析与验证重试。
- 建议值自动保存方案，或低于模型输出上限时抬升请求输出上限。
- 输入侧/上下文窗口探测（现有连接测试明确声明不发现上下文窗口，维持不变）。
- 纯转录等无 LLM 任务的连接测试。
- 主翻译/审校方案与工具角色方案不同时，对其余角色方案的逐一测试（连接测试验证连通性配置本身，不是全部角色清单，见补充说明）。
- 词汇表中能力测试/验证重试新旧两版词条并存的清理（领域建模事务，另行处理）。
- 视频编码器的能力探测（ADR 0008，同名不同物，互不相干）。

## 补充说明

- 本 spec 落实 ADR 0016（三态语义）与 ADR 0017（行为分叉）。CONTEXT.md 当前存在裁决前后的重复词条，以 ADR 与后出现的新版定义为准——能力测试：不做输出上限探查、验证重试或建议值应用；验证重试：仅输出上限探查使用。
- 未配置请求输出上限时，现有探针上限折算逻辑（含思考预算扩容、工作上下文减半封顶）保留，继续用于能力测试与连接测试的小请求上限。
- 连接测试按工具角色解析方案：无独立工具绑定时从主翻译方案派生（剥离翻译调优字段），因此最常见的单 provider 配置下它同时覆盖主翻译连接；独立绑定工具方案时测工具方案，主翻译/审校方案的连通性不在其承诺内。
