# LLM 翻译性能：批并发执行与批规模缩放

## 问题陈述

我跑一次增强型 LLM 翻译，等的时间太长。进度条在全文分析、术语确认、高级校对审计这几段几乎不动——后来才知道，正式翻译批是 4 路并发的，但其余三个阶段的 LLM 请求全在串行一个个等；一次 30 分钟视频约 300 个请求里，近一半是完全串行的，其中审计段（约 80 批）独自占了比整个翻译阶段还长的墙钟时间。更气人的是，我在界面里把线程数调到 10，实际并发仍被模型配置方案里一个我看不到的默认值压在 4——旋钮是假的。

同时，我的模型上下文窗口有 128k+，我想用大批（比如几百条字幕一批）减少请求总数来提速，但翻译批处理上限只能调到 50；就算放开，今天的输出预留（固定 8192/4096 封顶）和请求超时（固定 120 秒）都不随批大小变——大批输出必然截断、长生成必然超时，放宽上限也形同虚设。任务中途取消时，已经翻好的批次全部丢弃，只能从头再来。我想知道时间到底花在哪个阶段，也没有任何一处能看到阶段耗时。

## 方案

把增强翻译的四个 LLM 阶段（全文分析窗口、术语候选、正式翻译批、审计批）的执行收进一个「批并发执行」模块：相互无依赖的批次以滑动窗口并发发出，批内依赖序列（如术语候选的主建议→校对裁决）保持原顺序串行。并发度直通任务级「并发请求数」旋钮（原线程数），模型配置方案里的并发上限降级为默认不夹的可选保护夹钳。

同时把批规模相关的参数从固定值改为随批缩放：翻译批处理上限放宽到 500（默认 10 不变，实际批大小仍由 token 规划向下收缩防超预算）；批规划的输出预留改为按主体输入比例估算；请求超时随请求输出上限延长。任务级构造单一 LLM 网关注入全部翻译消费点复用连接；翻译检查点改为每批完成增量写入；用量汇总增加各阶段墙钟耗时，让「时间去哪了」可见。

## 用户故事

**批规模与规划**

1. 作为一个字幕制作者，我想要把翻译批处理上限最高调整到 500，以便用大上下文模型时显著减少请求总数。
2. 作为一个字幕制作者，我想要实际批大小始终由 token 规划在工作上下文与输出预留约束下向下收缩，以便配置 500 也不会因超出预算而失败。
3. 作为一个字幕制作者，我想要批规划的输出预留随主体数按输入比例缩放，以便大批一次生成完整而不被截断后拆批重试浪费整次请求。
4. 作为一个字幕制作者，我想要大批请求的超时随请求输出上限延长，以便长生成不被固定 120 秒误杀。
5. 作为一个字幕制作者，我想要小批请求保持快速失败，以便瞬时故障快速进入重试而不是等满长超时。
6. 作为一个字幕制作者，我想要翻译批处理上限的默认值仍是 10，以便不主动调整时批行为不变。
7. 作为一个字幕制作者，我想要正式翻译批与审计批共用同一个批处理上限，以便两阶段批行为一致可预期。
8. 作为一个 CLI 用户，我想要 --batch-size 同样接受到 500 的值，以便 CLI 与 GUI 的批配置能力一致。

**批并发执行**

9. 作为一个字幕制作者，我想要全文分析窗口、术语候选、正式翻译批、审计批四个阶段的无依赖批次并发执行，以便总时长按并发度缩短而不是被串行阶段拖长。
10. 作为一个字幕制作者，我想要术语候选内「主建议→校对裁决」的先后依赖保持串行，以便高级校对的纠错视角语义不变。
11. 作为一个字幕制作者，我想要单批请求的失败降级行为与现在一致（机械重试后整任务失败、审计输出限额拆批），以便并发化不改变错误语义。
12. 作为一个字幕制作者，我想要任务取消时并发在途批次被及时放弃且已完成结果保留，以便取消干净且不丢成果。
13. 作为一个字幕制作者，我想要批数不超过并发度时跳过首批串行预热，以便小任务不为前缀缓存付纯串行代价。
14. 作为一个字幕制作者，我想要批数充足时保留首批预热，以便支持隐式前缀缓存的供应商继续享受缓存命中。

**并发控制面**

15. 作为一个字幕制作者，我想要并发度直接由任务级「并发请求数」控制并真实生效，以便调大旋钮真的变快。
16. 作为一个字幕制作者，我想要模型配置方案里的并发上限默认不夹，以便没有隐式压制。
17. 作为一个字幕制作者，我想要在模型配置方案里显式设置并发上限时它作为保护夹钳生效，以便对限流严格的供应商手动限流防 429。
18. 作为一个字幕制作者，我想要旧配置里遗留的默认并发上限值在升级时被清除，以便迁移后不被历史值静默压住。
19. 作为一个字幕制作者，我想要 429/服务端错误继续由既有退避重试（遵循 Retry-After）兜底，以便限流场景自动恢复。
20. 作为一个字幕制作者，我想要主翻译与高级校对绑定不同模型配置方案时各自吃满各自的并发额度，以便两个 provider 互不挤占。
21. 作为一个字幕制作者，我想要 GUI 与 CLI 的并发请求数默认统一为 10 且旋钮文案改为「并发请求数」，以便两个入口行为一致、旋钮名副其实。

**任务级网关与检查点**

22. 作为一个字幕制作者，我想要一次任务内断句、字幕优化、增强翻译、后处理压缩共用同一个 LLM 网关实例，以便复用连接且观测单通道。
23. 作为一个字幕制作者，我想要独立后处理任务在无翻译网关时照旧自建网关，以便独立后处理入口行为不变。
24. 作为一个字幕制作者，我想要翻译检查点在每批完成时按字幕 ID 增量合并写入，以便中途取消或崩溃不丢已完成批次。
25. 作为一个字幕制作者，我想要进度报告按完成批次滑动更新，以便大批任务不再长时间无进度反馈。

**交互语义保持**

26. 作为一个字幕制作者，我想要手动术语确认仍在全部术语候选解析完成后一次性弹出，以便确认交互不被并发化改变。
27. 作为一个字幕制作者，我想要手动审计确认语义不变，以便审计报告的呈现与选择流程照旧。

**观测**

28. 作为一个字幕制作者，我想要看到各 LLM 阶段（分析/术语/翻译/审计）的墙钟耗时汇总，以便知道时间去哪了。
29. 作为一个 CLI 用户，我想要 CLI 任务结束时打印各阶段墙钟与请求数汇总，以便无 GUI 也能评估优化效果。

## 实现决策

**批并发执行模块（新，增强翻译编排器内部）**

- 四个阶段（全文分析窗口、术语候选、正式翻译批、审计批）穿过同一个批并发执行接口：入参为批次序列、单批执行函数、并发度、取消令牌与完成回调；滑动窗口并发、取消传播、预热决策收进实现。
- 批内依赖序列（术语候选的主建议→校对裁决，必要时裁决复核）作为单批执行函数内部的串行序列保留，并发只发生在批次之间。
- 首批预热决策自适应：批数 ≤ 并发度时跳过预热直接全并发；批数充足时保留首批串行预热换取供应商前缀缓存。
- 后处理的语义修复窗口不纳入本模块（本期范围外）。

**批规划与请求参数缩放（遵循 ADR-0019）**

- 翻译批处理上限：增强翻译批配置的取值范围放宽到 1-500，默认 10 不变；正式翻译批与审计批共用；single 模式的批配置范围不动。
- 输出预留：由固定封顶改为输入比例式——主体输入估算 × 输出比（翻译约 1.2、审计约 1.3，审计含修正版与问题列表故略高）+ 固定 JSON 结构开销；仍钳制在工作上下文与用户配置的请求输出上限之内。
- 请求超时：由固定 120 秒改为基线 + 请求输出上限 × 每 token 时间系数；三种传输接口一致采用；小批保持快速失败。
- 自动档输出上限升档梯次（32k/64k/256k）不动；预留只管批规划，请求实际输出上限逻辑不变。
- 翻译批失败降级策略保持现状：机械重试后整任务失败；审计批输出限额拆批重试照旧。输出预留随批缩放后大批截断概率本身大幅下降。

**并发控制面（遵循 ADR-0018）**

- 每个 LLM 网关按模型配置方案维护一个并发闸，闸的大小直通任务级并发请求数。
- 模型配置方案的并发上限字段改为可选夹钳：默认 None（不夹）；仅显式设置时作为该方案的保护上限参与钳制。旧配置迁移时把遗留的默认值 4 清除为 None（无法区分显式与默认，需要限流的用户重设）。
- 任务级并发请求数（原线程数）：GUI 与 CLI 默认统一为 10，旋钮文案改为「并发请求数」。
- 429/5xx 继续由网关既有退避重试（遵循 Retry-After）兜底，不新增静态限流。

**任务级单一 LLM 网关**

- 字幕处理流水线线程构造一个任务级 LLM 网关，注入断句器、字幕优化器、增强翻译编排器，并传下给后处理的函数形消费点（压缩、语义修复、配音改写经既有借用 seam 使用，注入时不接管生命周期）。
- 独立后处理任务无翻译网关可传时照旧自建（借用 seam 语义不变：缺失时惰性构造并在用毕关闭）。

**检查点与进度**

- 翻译检查点从「全部完成后一次写」改为「每批完成按字幕 ID 增量合并写入」；并发下批次乱序完成，合并以字幕 ID 为准。
- 进度报告从阶段级百分比改为阶段内按完成批次滑动更新。

**观测**

- 阶段用量汇总（现有按角色/阶段的请求数与 token 聚合）增加墙钟耗时聚合，进审计报告与 CLI 末尾输出；数据源为既有每请求耗时记录。

## 测试决策

好测试只测外部行为：主 seam 用假网关按脚本返回结果或抛错，断言「发了什么请求、并发形状如何、结果如何合并」，不断言内部函数调用或私有状态。

- **主 seam（现有，不新建）：增强翻译编排器的 LLM 网关注入点。** 覆盖：四阶段请求的最大同时在途数不超过并发度（并发形状）；乱序完成时结果按字幕 ID 正确合并；术语候选内主建议→校对裁决保持先后依赖；取消时在途批次放弃且已完成批次保留；首批预热跳过与保留的条件；输出预留缩放下批规划产出的主体数（大批不再被固定封顶压小）；审计拆批路径行为不变；手动术语确认仍在全部候选解析后一次触发。先例：现有编排器假网关测试（脚本化网关按 stage 返回）。
- **次 seam（现有）：LLM 网关的适配器工厂注入点。** 覆盖：并发闸大小直通任务并发请求数；可选夹钳默认不夹、显式设置时钳制；旧配置遗留并发上限值迁移清除。先例：现有网关测试的假适配器工厂。
- **次 seam（现有）：LLM 适配器的 session/client 注入点。** 覆盖：三种传输接口的请求超时随请求输出上限延长（慢响应假 session 断言超时值）、小批保持基线超时。先例：现有适配器测试的注入 session。
- **次 seam（现有）：增强翻译 runner 的检查点回调。** 覆盖：每批完成即增量写、按字幕 ID 合并、中途失败后已写内容完整。先例：现有 runner 检查点测试。
- **次 seam（现有）：字幕处理流水线线程构造。** 覆盖：任务级单一网关传下断句/优化/翻译/后处理全部消费点。先例：现有流水线线程测试。
- **次 seam（现有）：阶段用量汇总。** 覆盖：墙钟聚合按角色/阶段正确累计。先例：现有请求日志/用量测试。
- **UI 层不新建 seam：** 沿用现有 offscreen QApplication 测试先例，覆盖批处理上限控件取值范围 1-500 与默认 10、并发请求数文案、旧配置迁移后并发上限清空。
- **CLI 层：** 沿用现有字幕命令测试先例，覆盖 --batch-size 接受到 500、默认 10、并发请求数默认 10。

## 范围外

- 后处理语义修复窗口的并发化（本期只做增强翻译四阶段，语义修复另行安排）。
- single 模式（单模型翻译）批配置范围的调整。
- 流式响应（stream）支持——进度以批完成粒度报告已满足反馈需求。
- 网关磁盘响应缓存的键设计与命中观测（既有 ADR 遗留调研项，另行处理）。
- 机械重试携带历史增长、token 估算 CPU 性能等次要优化。
- 供应商自动识别与方言推断。
- 全文分析/术语候选的请求形状变更（稳定前缀、术语注入、brief 结构全部不变，既有缓存设计不受影响）。

## 补充说明

- 本 spec 落实 ADR-0018（并发控制面收敛到任务级并发请求数直通）与 ADR-0019（批规划输出预留与请求超时随批规模缩放）；术语「翻译批处理上限」「批并发执行」已入领域词汇表。
- 500 是防呆上限不是承诺：实际批大小始终由 token 规划收缩，用户配置大批即承担对应的超时与成本后果。
- 请求内容语义零变更：主翻译与高级校对的角色分离（既有 ADR）、稳定前缀与块级术语注入的缓存设计（既有 ADR）均不受并发化影响——并发只改变批次发出的时序，不改变任何请求的内容与依赖顺序。
- 阶段墙钟汇总是验收仪表：并发化前后各跑一次同规模任务，四阶段墙钟对比即为优化效果的量化依据。
