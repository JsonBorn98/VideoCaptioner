# 模块内恢复检查点：翻译与后处理中断后从检查点继续

## 问题陈述

我跑一次长字幕的增强型 LLM 上下文翻译，要经过全文分析、术语确认、逐段翻译、翻译质量审计四段，几百到上千个模型请求；后处理还要再跑多轮观看问题修复。中途一次网络故障、一次超时、一次误点停止、一次软件崩溃，唯一的出路就是整个模块从头再跑，前面所有请求白花钱、白等时间。我知道术语表已经落盘、译文也在按批写检查点，但软件不会读回它们；全文分析出来的翻译上下文简报根本没落盘。批量任务跑到半夜断掉，第二天只能整批重来。上一轮我们明确说过「不做断点恢复」，现在这笔账已经大到必须做了。

## 方案

翻译模块和后处理模块各自在安全边界写恢复检查点，下次对同一输入再开始时自动发现、弹恢复提示，选「从检查点继续」就跳过已完成的部分，选「从头开始」就当没有检查点。翻译有四级恢复边界：全文分析完成（翻译简报文件）、术语确认完成（权威术语表）、每个正式翻译批（译文检查点）、每个审计批（审计检查点）。后处理有两类恢复边界：确定性阶段、压缩重译与语义修复完成后的阶段末，以及每个修复轮次归并验收后的轮末。

检查点身份只看输入、语言对和翻译方式；提示词、模型配置方案、后处理配置方案的变化记为配置漂移，在恢复提示里列出并在报告里标注，但不使检查点作废。失败、主动停止、崩溃三类中断都保留检查点。单个任务弹提示，批量任务和 CLI 无人值守默认继续，CLI 提供 `--fresh`。模块成功交付后清理检查点。网关响应缓存的保留期从 1 小时延长到 7 天，覆盖轮内、阶段内中断后重发相同请求的回放。完整 workflow 阶段之间仍按 ADR-0004 手动衔接，单模型 LLM 翻译与非 LLM 翻译不纳入。

## 实现决策

**恢复检查点与恢复 manifest（两模块共享的形状）**

- 每个模块、每个检查点身份一份恢复 manifest，作为唯一进度真相：schema 与版本、检查点身份（翻译为源字幕指纹、语言对、翻译方式；后处理为输入指纹、语言对）、规范化任务名、创建与更新时间、软件版本、冻结配置摘要（供漂移比对）、各级完成状态与已完成批次键、最后一次中断类型（失败或停止；崩溃时该字段缺失）。
- 源字幕指纹沿用项目术语表文件已有的算法：字幕编号与规范化源文本的稳定哈希，不含时间轴、不含译文。后处理输入指纹沿用任务过程目录既有算法。
- 写入顺序固定为「先原子替换检查点数据文件，再更新 manifest」；manifest 未登记的数据文件一律视为未完成。恢复只信 manifest；manifest 登记而文件缺失或不可读的级别视为未完成并告警，任务继续。
- 检查点数据文件与 manifest 不含 API key、完整 prompt 文本（只存哈希）和模型原始响应，遵守过程资产 manifest 的既有边界。
- 「恢复决定」回调：两个模块入口各新增一个可选回调，入参为恢复摘要（模块、身份、已完成级别与计数、检查点时间、漂移清单），返回「继续」或「从头开始」；未提供回调即默认继续，这是批量与 CLI 的路径。
- 漂移比对项。翻译：主翻译提示词哈希、高级校对提示词哈希、主翻译模型配置方案（方案名、模型、接口类型）、高级校对模型配置方案、翻译批处理上限、边界语境段范围。后处理：后处理配置方案冻结值哈希、翻译执行快照中的翻译方式、两角色方案与提示词哈希。任何漂移都不作废检查点，只进入恢复摘要与成果溯源。
- 恢复过的运行在翻译执行快照与过程资产 manifest 写入恢复来源（检查点时间、恢复时已完成级别）与漂移清单；翻译审计报告与 QA 报告据此各加一节标注。
- 成功交付后删除该身份下的恢复 manifest 与仅供恢复的数据文件；发布清单与过程资产导出不含它们。失败、停止、崩溃均不删。
- 「从头开始」：重写 manifest 为全部未完成（身份保留），数据文件由新运行按级覆盖，不预先删除。
- 恢复后进度百分比从恢复级别起算；阶段摘要按 ADR-0009 的口径输出一行「从恢复检查点继续，跳过 …」，不在原始日志里散写。

**翻译模块（增强型 LLM 上下文翻译）**

- 暂存目录身份从「任务名 + 语言对」改为「任务名 + 源字幕指纹 + 语言对」，四级检查点文件与恢复 manifest 都放暂存目录；成功发布后暂存目录整体删除（现状是发布后不清理，会让已完成任务被误当成可恢复）。
- 级别① 翻译简报文件：资产种类 context 重新加入种类表并定义 schema（版本、翻译上下文简报全部字段、去重后的疑难术语候选及其义项、出现字幕段编号、别名、代表语境所需引用），供术语阶段与完整翻译提示词组装直接消费。成功发布时与权威术语表、翻译审计报告、译文检查点一起复制到任务过程目录并登记 manifest；后处理过程资产发现按 JSON 可读性验证并复制，本轮不新增消费者（D07 简报复用维持未确认）。
- 级别② 权威术语表：沿用现有文件；恢复跳过路径等价于现有 EXACT 导入路径（跳过术语提议、校对裁决、校对回退、人工术语确认）。显式导入术语表同时存在时以显式导入为准，走现有分类逻辑。
- 级别③ 译文检查点：沿用现有按批增量合并写入；恢复 manifest 记录已完成字幕段编号集合（按批提交）；恢复时以 manifest 为准装载已完成译文，缺失或不一致的字幕段重新纳入待翻译集合并按当前配置重新规划翻译批，边界语境段照常取源字幕。
- 级别④ 审计检查点（新增）：每个审计批完成后写入该批结构化审计问题；批以其覆盖的字幕段编号集合为键。恢复时按当前配置重新规划审计批，键完全匹配的批直接采用，其余重跑；全部到齐后自动修复客观问题或人工审计确认照常进行。
- 编排器新增可选的恢复状态入参（简报、候选、术语表、已完成译文、已完成审计批），据此决定各阶段是否发请求；不改变任何请求内容、批内依赖顺序、稳定缓存前缀与块级术语注入。
- 主动停止路径与失败路径一致：保留暂存与 manifest，并写入中断类型。
- 单模型 LLM 翻译、非 LLM 翻译不接恢复 manifest，继续依赖既有 7 天块级结果缓存。

**后处理模块**

- 检查点位于任务过程目录（身份目录已由过程资产发现建立），作为瞬时资产种类登记进 manifest；模块成功时按现有「未再产生的种类除名并删除文件」规则清理，不为清理新写一条规则。
- 阶段末检查点：确定性阶段、压缩重译、语义修复完成、进入观看问题修复前写入，内容为工作字幕全量与截至该点的质量报告累积状态（阶段报告、压缩失败、速度结果、精确时间轴结论）。
- 轮末检查点：修复轮次归并验收后写入，内容为工作字幕全量与修复摘要（轮次号、请求计数、各问题身份尝试计数、已关闭区域、回退记录、下一轮反馈、候选与状态指纹）。修复循环通过完成回调把轮末状态交给运行器，运行器经资产库写入；修复循环自身仍不做磁盘 I/O，ADR-0021 的冻结上下文与确定性归并不变。
- 恢复：过程资产发现之后、进入处理之前读取 manifest；决定继续时装载工作字幕与累积状态，跳过前处理与后处理阶段，直接进入修复循环并恢复计数器；循环按既有逻辑重新扫描问题、继续下一轮。业务修复重试上限、轮次上界、连续传输失败上界均以恢复的计数继续，不重置。
- 主动停止与模块级失败保留检查点；分析模式不写；仅报告流程只写阶段末（没有修复轮次）。停止语义按 P05 不变：不交付部分成果、阻断下游、迟到结果不写回。
- 精确时间轴证据不进检查点，既有时间轴缓存已覆盖。

**入口适配**

- GUI 线程：字幕翻译线程与后处理线程各新增「需要恢复决定」信号和提交方法，页面弹对话框（标题、进度摘要、漂移清单、「从检查点继续」「从头开始」两个按钮），采用与人工术语确认相同的阻塞等待模式；完整 workflow 编排的单任务同样走这条路径。批量任务线程不接回调（默认继续），任务行状态加「已从恢复检查点继续」标注。
- CLI：subtitle、postprocess、process 增加 `--fresh`；无该旗标时默认继续并在标准输出打印恢复摘要；process 把旗标传递给翻译与后处理两个阶段。
- 网关响应缓存过期常量从 1 小时改为 7 天；键与值 schema 不变；连接测试仍不使用缓存；不新增用户设置项。

## 测试决策

好测试只测外部行为：从模块入口喂输入与按阶段脚本化的假网关，断言「哪些阶段发了请求、发了多少、过程资产目录里落了什么、最终成果是否与不中断运行等价」，不断言内部函数调用顺序或私有状态。

- **主 seam A（现有）：增强翻译模块入口。** 注入源字幕、翻译配置、临时输出目录、脚本化假网关、可选恢复决定回调。覆盖：在四个级别各制造一次中断（脚本抛错或取消），再对同一输入重跑，断言被跳过的阶段请求数为零、恢复阶段只重跑剩余批、最终初版字幕与审计报告和不中断运行等价；恢复摘要的已完成级别、计数与漂移清单正确；改提示词或模型后仍复用并在审计报告与翻译执行快照标注漂移；回调返回「从头开始」时四级全部重跑且 manifest 先被重置；未提供回调默认继续；源字幕文本改动后不发现检查点；manifest 登记但文件损坏时告警并视为未完成；显式导入术语表优先于检查点术语表；成功发布后暂存目录删除、任务过程目录含 context 资产；停止后暂存保留并记录中断类型；人工术语确认在术语表已完成时不再触发、人工审计确认在审计批全部到齐后触发一次。先例：现有增强翻译 runner 检查点测试（假编排器/假网关、临时工作区中查找译文检查点）与编排器脚本化假网关测试。
- **主 seam B（现有）：后处理模块入口。** 注入初版字幕任务、脚本化假网关、临时目录上的文件系统资产库、取消函数、可选恢复决定回调。覆盖：在第 N 轮归并后中断再重跑，前 N 轮不再发请求且尝试计数、已关闭区域、回退记录延续，最终后处理字幕、QA 报告、状态与不中断运行等价并带恢复来源标注；阶段末中断后恢复不重跑压缩重译与语义修复请求；停止后检查点保留但无交付、下游被阻断；成功后检查点文件删除且 manifest 除名、导出清单不含；分析模式不写检查点；后处理配置方案变化列入漂移且仍可继续；输入指纹不同不发现检查点；损坏 manifest 告警并从头。先例：现有任务 seam 测试、持久化与导出测试、修复执行假网关测试、轮次快照归并测试。
- **薄边界（现有）：网关响应缓存。** 注入捕获过期参数的假 diskcache，断言写入条目的保留期为 7 天，连接测试路径不写缓存。先例：现有响应缓存测试的注入缓存与坏缓存替身模式。
- **薄边界（现有）：CLI 命令函数。** monkeypatch 两个模块入口，断言无旗标时恢复决定为「继续」且打印恢复摘要、`--fresh` 时为「从头开始」、process 把旗标同时传给翻译与后处理。先例：现有翻译模式与后处理命令测试。
- **薄边界（现有）：线程与页面。** offscreen Qt 先例，断言翻译线程与后处理线程在有检查点时发出「需要恢复决定」信号并阻塞至提交、批量线程不发信号且行状态带续跑标注、编排单任务走提示路径。先例：现有字幕线程翻译模式与取消测试、流水线线程测试。
- 过程资产库的恢复 manifest 读写与清理不单独建公开测试协议，由主 seam A、B 的场景覆盖；既有低层资产库测试继续维护。
- 全部回归离线运行，不发真实模型请求；使用项目既有 uv 工具链。

## 范围外

- 单模型 LLM 翻译与非 LLM 翻译纳入恢复检查点。
- 完整 workflow 阶段级恢复、持久化任务记录、软件重启后的自动续跑状态机。
- 轮内已验收候选落盘、全文分析窗口级或单术语级检查点。
- 恢复检查点的导出、跨机器迁移、多任务合并。
- 后处理消费翻译简报文件（D07 简报复用另行决策）。
- 网关响应缓存保留期的用户设置项与容量治理。
- 批量任务的逐项恢复交互。
- 未完成检查点的保留期自动清理：未完成的检查点永久保留在过程资产目录，用户可自行删除。
- 翻译请求内容、批规划、并发、缓存前缀等既有语义的任何变更。

## 补充说明

- 本 spec 落实 [ADR-0022 模块内恢复检查点](../../docs/adr/0022-ticket.md)；术语见根词汇表 Subtitle Postprocessing（恢复检查点、检查点身份、配置漂移、恢复提示、从头开始、模块内恢复、后处理恢复边界）与翻译词汇表 Subtitle Translation（翻译恢复边界、翻译简报文件、译文检查点、审计检查点）；后处理设计记录 2026-09-16 一节记录了裁决与默认项。
- 现状事实：翻译上下文简报不落盘；译文检查点每批原子写但无读者；翻译暂存目录发布后不清理；后处理修复循环零磁盘 I/O；网关响应缓存键排除 task_id、保留 1 小时。两条内部先例（译文检查点写路径、响应缓存键设计）已记入本 feature 的灯塔参考。
- 本 spec 替代 ADR-0004 末段中模块内部的「不增加恢复入口」部分，修订 P01/P05 与 ADR-0021 的「不复用上游 checkpoint 交付语义」措辞：复用恢复机制不等于交付部分成果；原文保护、验收门槛、失败区域回退、停止不交付部分成果全部不放宽。
- 验收仪表：同一输入在某级中断后恢复，各阶段请求数对比即为省下的费用；恢复运行与不中断运行的成果等价性由主 seam 测试给出。
