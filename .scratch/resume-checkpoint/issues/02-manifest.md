# 02 - 翻译恢复 manifest 与术语表/译文两级恢复

**构建什么.** 作为字幕制作者，增强型 LLM 上下文翻译在正式翻译批中断（失败、主动停止、崩溃）后，对同一源字幕再次开始时自动发现恢复检查点：术语提议、校对裁决、校对回退与人工术语确认全部跳过、零请求，只对未完成字幕段重新规划翻译批；最终初版字幕、翻译审计报告、权威术语表、译文检查点与翻译执行快照和一次不中断的运行等价。

本票同时建立两模块共用的形状：恢复 manifest（schema 与版本、检查点身份 = 源字幕指纹 + 语言对 + 翻译方式、规范化任务名、创建/更新时间、软件版本、各级完成状态与已完成字幕段编号集合、最后中断类型），写入顺序固定为先原子替换数据文件再更新 manifest，恢复只信 manifest；模块入口新增可选「恢复决定」回调，入参恢复摘要（模块、身份、已完成级别与计数、检查点时间、漂移清单占位），返回「继续」或「从头开始」，缺省继续。manifest 形状与回调类型不依赖翻译专有类型，供后处理票复用。

暂存目录身份从「任务名 + 语言对」改为「任务名 + 源字幕指纹 + 语言对」，源字幕指纹沿用项目术语表文件的算法（字幕编号 + 规范化源文本，不含时间轴）；成功发布后暂存目录整体删除，失败与主动停止保留并写中断类型。权威术语表已完成时的跳过路径等价于现有 EXACT 导入路径；显式导入的项目术语表文件优先于检查点术语表。译文检查点沿用现有按批增量写入，恢复时以 manifest 的已完成集合为准装载译文，缺失或不一致的字幕段重新纳入待翻译集合。「从头开始」重写 manifest 为全部未完成，不预删数据文件。阶段摘要按 ADR-0009 口径输出「从恢复检查点继续，跳过 …」一行。

本票不含翻译简报文件（全文分析在本票仍会重跑）、审计检查点、配置漂移比对，分别由后续票交付。遵守 ADR-0022；不改变任何请求内容、批内依赖顺序、稳定缓存前缀与块级术语注入。
