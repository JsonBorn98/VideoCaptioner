# 字幕后处理性能治理：有界并发、可观察执行与及时停止

## 问题陈述

我对一份长视频的初版字幕执行独立后处理，界面长时间停在“正在修复观看问题（第1轮，899个未解决）”。我不知道它正在等待模型、逐条校对、反复重试，还是已经停止工作；点击停止也不能保证及时结束等待。我需要后处理真正变快，而不是只让进度条动起来，同时不能牺牲原文保护、译文语义质量或必要的观看约束修复。

本次样本是 DHH Future of Programming 的初版双语字幕，共 7,257 个字幕段，已有状态与报告记录 899 个未解决问题。只读调查确认观看约束修复路径采用“每批主修复 → 逐修复主体高级校对 → 下一批”的串行请求，轮内不报告批次进度。活动日志窗口内请求基本逐条相接，主修复请求中位耗时约 163 秒，单次校对约 4.7 秒；这些统计跨中断重启，不能作为单次完整任务基准。

日志另有约 4.4 小时无请求记录的静默空档，尚未证实成因。串行吞吐低、进度缺失、等待不可及时取消是已确认缺口，但不能因此宣称已解释或修复历史静默空档。

## 方案

在不降低质量的前提下，治理同类长字幕的完整后处理执行体验：先建立可复跑的后处理性能基准，再让相互独立的修复请求受控并发，合理组织主修复和高级校对批次，减少重复计算与无效请求。各批使用统一修复轮次快照，结果按确定顺序归并并重新验收，避免完成顺序改变字幕内容、问题归属或回退范围。

页面默认显示阶段、批次进度、问题验收状态和耗时，展开后显示在途请求、等待、重试与限流详情。请求的排队、网络和退避等待均有明确边界且可取消；点击停止后尽快结束本地任务，不等待模型自然返回，迟到结果不得写回或触发下游。不新增断点恢复，不承诺撤销服务端已接收的请求或停止计费。

保持原翻译方式及角色配置、必要校对、原文保护和既有质量门槛。整任务不设强制完成时限，不靠跳过问题或减少必要修复提速。验证先采用离线基准和受控响应，再在另行确认样本规模与费用上限后使用真实模型小样本；不默认重跑整片。

## 实现决策

### 1. 业务边界与不变式

- 本轮覆盖独立与编排后处理的真实耗时、进度、请求等待和停止；修改共享调用层只限于实现这些能力所需的兼容改动，不重构全应用调度。
- 保持初版快照不可变，输入文件不可回写；后处理字幕单独交付。测试和基准使用隔离输出位置，不覆盖用户现有过程资产。
- 遵守已接受的 ADR-0018（并发控制）、ADR-0019（容量与超时缩放）、ADR-0020（后处理职责与修复规则）及 ADR-0021（同轮冻结与确定性归并）。实时反馈和阶段摘要遵守 ADR-0009 的前端呈现、文件日志分工。
- 沿用原任务翻译执行快照中的方式、角色、提示词和已验证过程资产。借用网关生命周期不等于改用工具角色或剥离翻译角色参数；不得为提速降级模型、减少必要校对、修改推理配置或重跑上游全文分析。
- 维持现有能力开关与仅报告修复模式，不新增快速低质量模式；性能评估覆盖后处理各本地阶段，不把自动修复以外的阶段武断视为零成本。

### 2. 修复轮次快照与候选归并

- 每轮开始固定完整字幕、原始问题身份与映射，基于此版本规划主体、边界上下文和主修复载荷。主体重叠/相邻沿用合并规则，仅上下文重叠时不扩大修改目标。
- 并发 worker 只产生带身份与版本的候选、校对结果和错误，不直接修改完整字幕、业务重试簿记或交付状态。
- 高级校对必须绑定主修复候选版本；其视图以轮次快照为底，在对应修复主体内叠加本次合法候选。边界上下文不读取其他并发批次刚完成的修复，同一校对批中的多个主体分别保持候选映射，不能用完成时序改变上下文。
- 主修复到其校对保持先后依赖；不同主体链之间可重叠执行，不设置无必要的“全轮主修复全部完成后才开始任何校对”的屏障。
- 单一协调端按稳定的问题身份和固定段序归并，兼容一对多拆分、区域回退及索引移动。异步完成顺序不影响候选应用顺序、回退范围、计数或下一轮输入。
- 相同轮次快照、配置和对应响应集合在任意完成顺序下必须产生相同字幕、验收与回退结果；这不是要求真实模型在两次独立请求中输出逐字相同。
- 每个候选保持原文等价、结构、时间安全、语义及观看约束检查；归并后重检完整字幕。新候选必须满足既有单调改善、防重复和防震荡规则，已通过问题不因其他问题重试而重新处理。
- 内部工作状态不等于可交付成果。完整任务完成前，即使部分候选已经验收，也不为主动停止任务交付部分后处理字幕。

### 3. 主修复与高级校对的容量规划

- 将现有容量规划真正接入执行，预算覆盖完整序列化请求，包括提示词、主/译文本、问题信息、术语等资产、边界上下文、反馈和结构化输出开销；不能仅估算主体裸文本。
- 主修复与高级校对分别依据其模型工作上下文、请求输出上限和请求形状预留输出。输出估计覆盖一对多片段、原译对应与协议开销，沿用既有可用 token 规划能力，不把固定主体数当容量保证。
- 请求主体计数与字幕段数、问题数分别记录。现有每批最多 10 个修复主体可作为第一版基准的内部起点，不新增面向用户的重复批大小旋钮；调整须有基准与质量依据。不得将上游“翻译批处理上限”的字幕段计数无解释地套成修复主体计数。
- 超容量时先减少批内主体数量；单主体仍放不下，再按既有顺序缩减边界上下文。零上下文仍不足时保留内容并明确报告容量不足，不截断原文、不静默拆坏原子主体。
- 高级校对支持容量允许时批量携带多个已经合格的主修复主体，不再把逐主体物理请求作为固定协议；保留主体及输出片段身份、独立错误与逐项验收。批次应由稳定输入分组形成，不能让网络完成速度随机改变质量上下文。
- 校对不应为了凑满大批无限等待；容量不足或只有一个可用主体时允许小批。不得通过漏校对、只校对抽样或全片再次校对来换取表面吞吐。
- 输出截断、结构无效和局部缺项分别可观察。真正截断不能当完整候选应用；缩批或失败处理必须遵守有限尝试边界，不能另造不计数的递归重试。局部可独立验证的成功项与失败项保持隔离。
- 不以性能优化名义抬升用户请求输出上限、放宽模型容量或自动变更用户配置；不可容纳项用明确状态报告。

### 4. 有界并发与入口配置

- 优先复用现有批并发执行能力及网关，而不是另建一套互不相知的线程池和限流体系。复用前检查结果收集、取消传播、等待退出和回调行为；不复用上游翻译的 checkpoint 交付策略。
- 按既有任务并发请求数和每 profile 显式保护上限限制实际在途请求；同 profile 的主修复/校对共享保护额度，不同 profile 的额度独立，不能由嵌套线程池把上限相乘。
- 保持有界滑动调度和背压，不一次性创建与整片问题数量等大的运行任务队列。不因固定归并顺序让无依赖网络任务必须串行等待；候选缓冲同样有界。
- 完整 workflow 使用任务冻结的并发设置；独立 GUI/CLI 后处理从既有执行配置建立冻结值，不悄悄退回网关默认值。没有已有可配置值时沿用权威默认值，并显示实际生效值，不在功能页添加跨模块设置快捷区。
- 请求重试、主修复、校对和缓存命中均纳入正确任务身份；缓存不改变取消、版本和验收要求。不得用暖缓存命中冒充真实模型并发提速。
- 预热、调度窗口、组批大小等内部调优服从基准，不把缺乏收益证据的首批串行等待设为必经步骤。

### 5. 请求期限、传输重试与失败语义

- 每个逻辑请求建立覆盖排队、传输尝试及重试退避的有限等待预算，并记录各部分；网络分阶段 timeout 不替代端到端期限。输出规模可以延长合理网络窗口，但所有等待都有明确上界。
- 尊重角色真实请求参数与既有超时缩放原则，不把工具角色默认值或某次观测时长当作所有模型的固定 timeout。数值由基准与现有配置确定并在验收前锁定，不承诺未经测量的整片完成时限。
- 检查 SDK、HTTP 适配器及网关的尝试边界，禁止不可见的嵌套重试乘积逃出总期限；既有重试原因分类和上限如需改动，必须保持兼容并有回归证据。
- Retry-After 不被任意忽略或缩短后提前重发；若要求等待时间超过剩余期限，明确结束等待并报告原因，而非无限 sleep。
- 传输重试与业务修复重试分别计数。保持初始修复提交不计入业务重试、默认最多 4 次业务修复重试，以及现有轮次/连续传输失败防无界约束；新调度不得增加实际尝试机会。
- 容量不足、传输耗尽、响应不合法和业务质量不通过应明确区分，并映射回既有问题状态、告警及回退规则。不把超时自动记为已解决，也不将一次局部超时无条件升级为整片失败。
- 高级校对失败继续遵守既有“保留已通过主修复候选并明确告警”的行为，不改成静默宣称校对成功；批量化不扩大失败范围，合法校对项仍需逐项验收。
- 修复耗尽回退保留其他成功区域，未解决区域不记为通过；合法的带警告结果允许既有下游继续。无效初版、模块级失败和主动停止阻断下游。

### 6. 后处理主动停止

- 取消属于当前任务，贯穿本地阶段、调度、并发槽等待、网络调用、退避、候选应用及交付边界。调度端观察到停止后不再出队新工作或发起重试；请求发送前有最后一次取消检查，竞态中已经发送的请求按在途请求处理。
- 信号量排队和退避使用可取消等待；仅在不可中断 sleep 前后增加检查不满足本要求。
- 为在途请求提供任务/请求级尽力中断通道。本地任务终止不依赖模型自然完成或普通网络 timeout；不能通过关闭其他任务仍在使用的共享 client 实现取消。
- 请求返回后、校对应用前、候选归并前及成果交付前重新确认取消状态与任务版本，防止最后一批、最后一次校对和任务完成竞态产生迟到写入。停止与交付使用明确的终态竞争规则：停止若先于交付提交被接受，交付不得继续；已提交完成的任务不被伪装成取消成功。
- 主动停止不更新后处理工作稿、不交付部分后处理字幕、不导出过程资产交付副本、不触发下游；保留初版快照并返回阻断状态。正常完成信号不能在取消后补发。
- 可以保留用于诊断的任务元数据、请求状态和取消记录，但不把它们当作恢复检查点或可交付部分成果。既有响应缓存不是本轮新增断点恢复协议。
- 尽力终止传输并释放任务资源；残留回调必须被隔离，不得继续调度、写入字幕或持有无限后台工作。用重复启动/停止验证连接、线程/任务和并发槽没有持续泄漏。
- 明示本地停止不能保证服务端撤销请求或停止计费。不以关闭应用进程、终止无关工作作为正常取消机制。

### 7. 进度与诊断

- 默认摘要展示当前阶段、当前轮次、批次完成数、已解决/待验收/未解决状态和运行耗时；展开详情展示主修复与高级校对的批次、有效并发、在途请求、排队、等待期限、退避与重试原因。
- 批次和问题计数有不同口径：模型返回表示收到响应，不表示问题解决；只有归并后的验收通过才计入对应解决状态。进入下一轮、拆分、回退或重新规划时明确更新分母，不能把变化隐藏在看似单调的假百分比中。
- 规划、本地处理、等待模型、校对、归并验收、保存和终态均有阶段事件。长调用期间用轻量状态刷新显示等待时长，UI 线程不执行阻塞工作，不靠每 token 流式返回才能响应用户。
- 沿用现有进度回调和 Qt 信号，必要时增加后处理范围内的可选结构化事件能力，并兼容现有简单百分比/文案消费者；不建设全应用重量级进度协议。
- GUI/CLI 渲染与文件诊断共享结构化事实，控制台不依赖日志级别副作用。CLI 保持普通/详细/安静模式习惯；GUI worker 不直接操作控件。
- 请求记录在开始时即能关联任务、轮次、批次、主体/问题身份、角色及尝试；完成、缓存命中、超时、取消和重试分别记录。发生突然退出时，只有开始没有终态的记录可被识别为未闭合，不伪造成功或已确认失败。
- 阶段耗时区分本地 CPU/处理墙钟、并发请求 duration 总和、排队、退避与任务墙钟；不得把跨重启、含空档的总跨度比值称为活动并发度。是否支持字段级 CPU 计时依本地基准测量方式明确标注。
- 不为诊断启用完整 prompt/响应/推理正文记录，不记录密钥、认证头或内部连接秘密；元数据在内容日志关闭时仍可关联。日志与进度避免逐字符/逐 token 大量事件，不能成为新的瓶颈。
- 正常、带告警完成、停止和失败均有终态及摘要；进程异常退出只承诺留下已写出的事件证据，不承诺恢复或保证最后一条事件落盘。

### 8. 基准先行与交付门槛

- 第一个实施切片先建立当前版本离线基准与可复跑命令，固定初版样本标识/指纹、配置、角色请求参数、代码版本、运行环境、缓存冷热、并发设置及受控模型响应。DHH 原始内容保持本地，公共回归采用合成或去敏 fixture。
- 基准同时包含长字幕本地管线、充分多的独立修复主体、主修复慢/校对快的依赖场景、混合主体大小、局部失败、取消与限流。报告请求逻辑数/真实尝试数、主/校对批大小与 token 估计、耗时分布、最大在途数及本地阶段成本。
- 基准切片交付一份验收矩阵，记录实测基线、样本数/重复次数、噪声区间和明确数值门槛：并发场景墙钟改善、主/校对请求数量、各等待阶段停止响应、UI 状态刷新及本地阶段不得回退的容忍范围。矩阵须在优化切片开始前固定，不能看见优化结果后随意降低门槛。
- 数值尚无实测依据，因此本 spec 不伪造提速倍数、整片分钟数或停止毫秒 SLA；to-tickets 应把基准和门槛产物作为后续性能实现/交付的明确阻塞依赖，而不是把验收标准留到交付时临时决定。
- 结构性硬门槛不依赖真实服务速度：有足够独立工作且额度大于 1 时请求确有重叠，实际在途不超配置/保护上限，乱序结果一致，等待取消不依赖模拟服务自然返回，迟到结果无副作用，必要校对覆盖不减少。
- 改变组批使请求数量不同的场景，同时报告每主体覆盖、请求数、token 和模型模拟负载；不能仅凭每请求固定延迟的模型声称真实 token 生成吞吐提升。缓存冷/热分别比较。
- 小样本真实验证覆盖超长原文拆分、译文修复、相邻/上下文重叠、多主体校对、局部失败与时间边界，人工或既有审计复核内容质量；保持相同模型与角色设置。真实费用/调用范围在执行前另行批准，费用接近上限时停止测试，不改变正式产品的质量策略。
- 若未获真实请求授权，明确标注真实模型质量与性能验证未执行，不能用离线测试替代“已经验证真实质量”的结论。整片验收只在另外明确授权后运行。
- 静默空档用任务级事件和故障注入覆盖可能的本地停滞、排队、在途网络和退避；无法重现历史现场时交付记录必须保留“历史空档未归因”，不把缺少复现伪装成修复成功。

## 测试决策

### 已确认的主要测试入口

用户在本次 to-spec 明确选择“完整任务为主”。复用现有 `run_postprocess_task` 作为主要业务 seam：传入初版字幕与任务配置、替换模型响应、触发取消并收集进度，从外部观察后处理字幕、报告、警告、输出文件、活动字幕和下游门禁。测试穿过实际规划、修复、校对与归并，不逐个 mock 内部函数，也不让核心验收依赖线程池种类或内部方法调用顺序。

主入口之外仅补必要的边界测试：真实网关/适配器到受控本地服务的取消与 timeout，及 GUI/CLI 对进度和停止的呈现。假网关证明不了 HTTP 在途取消、SDK 隐式重试、共享连接隔离和真实信号量等待，这些必须由传输边界测试覆盖；不能用假网关“瞬间取消”替真实行为背书。

### 测试范围与场景

1. **完整任务与资产交接**：独立、编排、CLI 三种入口，已验证的翻译执行快照，增强/普通/非 LLM 与仅报告模式；正常交付、修复耗尽局部回退、模块级失败和主动停止的活动字幕及下游门禁；输入文件和原始资产不变。
2. **快照与确定性**：同一响应集合正序、逆序和任意完成顺序；跨批共享上下文、合并主体、多问题身份、一对多拆分、重复候选、末批回退及下一轮重检。断言最终字幕、问题身份、计数和回退语义相同，不断言真实模型重复调用逐字相同。
3. **并发与依赖**：通过受控响应屏障观察多个独立请求确已同时进入；高级校对不早于对应主候选；同/不同 profile、并发值 1 和大于 1、显式保护夹钳、少量批次与长短批混合。断言额度与语义，不依赖易抖动的短 sleep 判断重叠。
4. **容量与校对批量化**：主/校对不同容量、完整 prompt 开销、一对多输出预算、减少主体优先于减少上下文、零上下文仍不可容纳、多个主体共同校对、局部缺项/错误/截断及其有限重试。检查无内容截断、无漏校对、无无界调用。
5. **停止全路径**：本地处理、等并发槽、等待响应、退避、主修复/校对返回竞态、末批/末次校对、归并与交付边界。停止先于交付时不产生正常完成、不写后处理成果、不更新工作稿、不触发下游；迟到结果和重复回调无副作用。
6. **真实传输边界**：本地受控服务提供永不结束但可主动释放的响应、缓慢分段数据、连接/读取停滞、429 与长 Retry-After、服务端错误；服务未自然结束时本地取消仍完成。所有测试有清理与总超时，验证 SDK 尝试数、端到端期限、共享 client 隔离和重复取消不泄漏。
7. **失败恢复**：传输失败不消耗业务修复重试，业务仍为初始提交加最多 4 次；容量失败、重复、无改善、轮次上界、连续传输失败、校对失败保留合法主候选的告警语义；同批成功与失败项互不误伤。
8. **进度与终态**：请求返回但未验收不算解决；轮次内有批级状态和等待时长；重规划分母变化明确；取消后不会补发成功；内容日志关闭仍有完整任务关联；GUI 摘要/展开详情和 CLI 详细/安静模式来自一致事实。
9. **性能与质量门禁**：运行基准矩阵，以冻结门槛比较优化前后；本地无模型场景无明显回退；请求并发不以减少必要处理、空实现质量检查或暖缓存作弊。真实小样本与人工质量复核单独报告，未经授权不执行。

### 现有测试先例与测试纪律

- 仓库已有修复执行假网关、规划容量、runner 结果/回退、翻译到独立后处理资产交接、后处理线程取消门禁及网关注入等待函数的测试，可直接扩展行为场景。
- 优先将跨规划、执行、归并和交付的回归收敛到完整任务入口；已有低层测试继续维护，但不为每个新内部辅助函数再创造一个公开测试协议。
- GUI 沿用 offscreen Qt 与信号观察，避免从 worker 直接触碰控件；传输测试使用 loopback/本地 stub，不访问真实 provider。
- 测试通过进程内事件、受控时钟或服务器屏障控制时序；性能测试使用稳定重复采样，正确性测试不绑定机器速度。真实墙钟只用于不能用逻辑时钟证明的停止/界面响应边界，并使用基准确定的阈值。
- 网络访问、真实 LLM 与高费用场景保持独立标记和显式授权；常规离线回归不需要 API key。运行命令优先使用项目既有 uv 工具链，不为本轮默认引入全局依赖。

## 范围外

- 全应用统一调度重构、翻译四阶段重新设计、替换 provider 或模型、自动修改推理强度和用户模型配置。
- 降低质量的快速模式、减少必要修复/校对、放宽原文/语义/观看门槛、设整片 deadline 强制交付半成品。
- 新增停止或重启后的断点恢复、保存未完成批次以续跑、取消后交付部分后处理成果；上游已有 checkpoint 行为不因此改变。
- 保证服务端取消或停止计费、远程进程管理、通过终止整个应用实现正常停止。
- 重做字幕编辑器、样式导出、媒体对齐算法或所有旧速度算法；实际基准若发现相关本地阶段是本轮瓶颈，只进行保持外部语义的针对性优化。
- 全应用重量级进度事件总线、必须依靠 token streaming 的展示协议、默认开启完整内容日志。
- 网关磁盘缓存协议重构、跨任务共享未验收候选、扩大过程资产发现规则；既有缓存仅按冷/热状态验证与隔离。
- 未经另行授权的真实整片对照、把 DHH 字幕正文/密钥/内部连接资料提交公共仓库、将本地 tracker 发布到外部服务。
- 对历史 4.4 小时静默给出未经复现或追踪支持的确定归因，或把本 spec 当作故障已经修复的证明。
