## Shoals
- [Windows离线基准必须显式UTF-8读取报告和脚本](scripts/postprocess_benchmark.py) — 本机uv Python默认GBK，Path.read_text()读取含中文基准脚本复现UnicodeDecodeError；JSON/脚本/日志读取显式encoding='utf-8'，子进程文本捕获也指定编码，避免把编码失败误判为业务或性能失败。
- [test_runner_owns_single_cancelled_terminal_event 偶发失败的等待循环对不上事件时序](tests/test_postprocess/test_progress_frontends.py:186) — offscreen Qt 子进程测试用 processEvents 轮询等首个 waiting 事件（10s 预算）再 thread.stop()，之后 15s 等 cancelled 信号。实测干净 HEAD 复现 6 次中 2 次失败：AssertionError: [] ——stop 后 15s 内 cancelled 信号未到。可能原因：queued pyqtSignal 在无人 processEvents 的间隙积压、QThread 清理慢于 15s、或 stop() 路径本身有慢分支。该 flake 与票 08 分槽修复无关（stash 验证），但拖慢全量回归判断（每次全量跑都可能红）。修复方向：把等待循环改为事件驱动（信号槽触发置位），或延长预算/重试。
- [requests.Session.close 不解除另一线程里阻塞的 read（watchdog 取消模式照搬 openai 路径会 5s 挂满 join）](videocaptioner/core/llm/adapters.py) — watchdog 模式封装阻塞请求时，close 的语义随 HTTP 栈不同：httpx/openai SDK 的 client.close() 会解除另一线程的阻塞 read，requests.Session.close() 不会。且主循环 while not done.wait(poll): if cancelled(): close() 在 close 后继续等 done——对 requests 会死循环（done 永不置位），对 httpx 恰好掩盖。修法：close 恰一次后 break 出等待循环，join 上界按传输栈配短值，未解除即按可重试传输错误上抛。新测试 test_native_transport_cancel_is_prompt_not_timeout_bounded 复现（修复前 anthropic/gemini 各 5s join 挂满）。
- [tests/test_ui 子进程 Qt 脚本随机段错误（0xC0000005）是既有环境噪声，不是回归——单变量重跑会骗人（stash 4/4 过也是运气）](tests/test_ui/test_postprocess_interface.py) — tests/test_ui 里用子进程跑 Qt 脚本的测试会随机段错误 (exit 3221225477/139, faulthandler 只报 'no Python frame')。双盲验证：把我对 postprocess_interface.py 的改动 stash 掉后同样 3/10 崩——与改动无关，是 qfluentwidgets 构造/主题路径的本机环境崩溃。交付时不要把这类段错误当回归追（单文件重跑或实机人工点验才是出口）；它是 UI 基线的既有环境噪声。
