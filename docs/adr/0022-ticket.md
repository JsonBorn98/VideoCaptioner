# 模块内恢复检查点

背景：ADR-0004 末段、后处理设计记录 P01/P05 与 ADR-0021 先后把断点恢复排除在当轮范围外，结果是逐批写出的译文检查点全仓库无读者，中断后唯一出路是整模块重跑，长字幕的全文分析、术语确认、逐段翻译、审计与修复轮次全部重新计费。2026-09-16 决定：增强型 LLM 上下文翻译与字幕后处理各自在模块内部写恢复检查点（翻译四级：全文分析完成、术语确认完成、每翻译批、每审计批；后处理两类：阶段末、修复轮次归并验收后的轮末），模块开始时按检查点身份（源字幕指纹或输入指纹 + 语言对 + 翻译方式）自动发现并弹恢复提示，单任务由用户选「从检查点继续」或「从头开始」，批量与 CLI 默认继续并可用 --fresh 从头；失败、主动停止、崩溃三类中断都保留检查点。理由：LLM 费用集中在两模块内部，workflow 阶段间已有阶段 SRT 可手动衔接，不值得为此引入持久化任务记录；批末与轮末是既有的一致性单元，复用它们不触碰「不交付未完整验收成果」和「迟到结果不得写回」的既有约束。

有效性采用宽松口径：提示词、模型配置方案、后处理配置方案的变化记为配置漂移，只在恢复提示中列出并在审计报告或 QA 报告中标注，不使检查点失效；术语是用户确认过的决定，改一个提示词就丢掉全部进度对用户代价过高，且用户始终可选从头开始。轮内候选不落盘，轮内中断依赖网关响应缓存回放，缓存 TTL 由 1 小时延长为 7 天。

本决定替代 ADR-0004 末段「不增加恢复入口或自动续跑状态机」中模块内部的部分，workflow 阶段级不自动续跑的约定保留；修订 P01/P05 与 ADR-0021「不复用上游 checkpoint 交付语义」的措辞：复用恢复机制不等于交付部分成果。单模型 LLM 翻译与非 LLM 翻译不纳入，继续依赖既有 7 天块级结果缓存。

## Considered Options

- 严格全匹配才复用：改一个提示词即丢掉已确认术语，否决。
- 显式 --resume 或「从检查点继续」按钮：崩溃重开后按钮不存在，覆盖不到最需要恢复的场景，否决。
- workflow 阶段级恢复加持久化任务记录：范围过大，阶段 SRT 已够手动衔接，否决。
- 轮内已验收候选落盘：需为未归并候选定 schema 并与修复轮次快照版本绑定，改由响应缓存回放覆盖，否决。
- 全自动静默复用：用户改提示词想重译时会被静默复用，否决。
