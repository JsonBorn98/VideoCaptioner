# 批规划输出预留与请求超时随批规模缩放

背景：批规划输出预留固定封顶 8192（翻译）/4096（审计）、请求超时固定 120s，均不随批规模变化；批处理上限放宽到 500 后，大批输出约 12-15k tokens 超预留必截断、生成 2-5 分钟必超时，放宽形同虚设。决定：翻译批处理上限 50 → 500（默认 10 不变，只防呆不保证批大小，实际大小由 token 规划向下收缩）；输出预留改为输入比例式（主体输入 × 输出比 ≈1.2/1.3 + JSON 开销，翻译/审计分别取值），仍受工作上下文与用户请求输出上限钳制；请求超时改为基线 + 输出上限 × 每 token 系数，小批保持快速失败、大批自然获得长窗口；自动档输出 cap 升档梯次 32k/64k/256k 不动。被否决：仅抬固定 ceiling（与实际输出规模仍不挂钩）、每主体上限式（最保守但批无谓变小）、超时固定抬高默认（小批故障也要等满长窗口）。用户配置大批即承担配置后果，失败降级策略保持现状（预留缩放后大批截断本身变稀有）。
